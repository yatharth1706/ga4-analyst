  Candidates:

  1. Hide Gemini's message format behind the LLM seam (Strong). LLM is a
     Protocol, but its interface is Gemini's contents/parts dicts. The agent
     loop, history.py, FakeLLM and seven agent tests all depend on that format;
     the tests index into ["parts"][0]["functionResponse"] directly. Two
     adapters already exist (Gemini and the fake), so the seam is real. Only its
     interface needs to change.
  2. Test the query runner through its interface (Strong). BigQueryRunner builds
     its own client, so tests can only reach check_dry_run and the private
     _to_json_value. Three things in run() have no test:
     - that the dry-run check happens before the real run;
     - the byte cap and timeout;
     - the error cleanup that keeps the request URL and project name out of
       messages.

     That's where the main SQL-safety decision lives. Passing the client in
     fixes it, and lets guard.py fold into the runner.
  3. One module for a turn's queries (Worth exploring). Each executed query is
     shaped three ways in three files: what the model sees, what the browser
     gets, and what the next turn remembers. The row caps (MODEL_MAX_ROWS,
     PREVIEW_ROWS) are scattered across those files, and history.py imports from
     tools.py.
  4. Give the event stream its own module (Worth exploring). The event names are
     string literals at 7 places in the backend, and types.ts mirrors them by
     hand. If the two sides drift apart, no test fails.
  5. Attach chart data in the reducer (Speculative). Matching a chart to its
     query's result happens in AssistantMessage, and Chart.tsx re-checks the
     columns the backend already validated.

  My top pick is #1, then #2 as a quick follow-up. #1 also makes "swap the model
  provider" a change to one adapter.
